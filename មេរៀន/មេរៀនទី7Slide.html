៧.១.១ ស្ថាបត្យកម្ម Relational Database (RDBMS)

Relational Database Concepts: Tables, Entities, Attributes, and Tuples

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY
🎯 គោលគំនិត ៖ RDBMS (Relational Database Management System) រៀបចំទិន្នន័យជាទម្រង់ តារាងទិន្នន័យ (Tables) ដែលមានជួរឈរ (Columns/Fields) និងជួរដេក (Rows/Records) ព្រមទាំងភ្ជាប់ទំនាក់ទំនងគ្នាតាមរយៈ Keys។

C1 សមាសភាគនៃ RDBMS

  • Database ៖ កន្លែងផ្ទុកតារាងទិន្នន័យជាច្រើនដែលទាក់ទងគ្នា។
  • Table (Entity) ៖ តារាងប្រធានបទមួយ (ឧទាហរណ៍ tbl_students)។
  • Column (Field / Attribute) ៖ ចរិតលក្ខណៈនៃទិន្នន័យ (ឈ្មោះ, អ៊ីមែល, GPA)។
  • Row (Record / Tuple) ៖ ទិន្នន័យរបស់បុគ្គលម្នាក់ៗជាក់ស្តែង។

MySQL Engine

MySQL គឺជាប្រព័ន្ធ RDBMS ប្រភេទ Open-Source ដ៏ពេញនិយមបំផុត ដែលដើរតួជាម៉ាស៊ីនផ្ទុកទិន្នន័យ (Storage Engine ដូចជា InnoDB) គាំទ្រប្រតិបត្តិការ ACID Transactions និងគ្រប់គ្រងទិន្នន័យរាប់លាន Records ដោយរលូន។

• ប្រើប្រាស់ Default Port: 3306
• Default Administrative User: root (គ្មាន Password ក្នុង XAMPP)

រចនាសម្ព័ន្ធតារាងទិន្នន័យ (Table Structural Components)

Anatomy of a Database Table: Entities, Attributes, Tuples, and Primary Keys

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY
សមាសភាគ (Component) ឈ្មោះបច្ចេកទេស Database ការពន្យល់ និងឧទាហរណ៍ជាក់ស្តែង
Table (តារាង) Entity / Relation សំណុំទិន្នន័យប្រធានបទតែមួយ (ឧទាហរណ៍ tbl_students)
Column (ជួរឈរ) Field / Attribute លក្ខណៈនៃទិន្នន័យ (ឧទាហរណ៍ id, fullname, email)
Row (ជួរដេក) Record / Tuple ទិន្នន័យម្នាក់ៗជាក់ស្តែង (ឧទាហរណ៍ Record របស់និស្សិត សុខ ជា)
Primary Key (PK) Unique Identifier កូនសោចម្បងសម្គាល់ Record នីមួយៗមិនឱ្យជាន់គ្នាដាច់ខាត

💡 Table Prefixing Strategy ៖ ក្នុងការអភិវឌ្ឍ Web Applications ជាទូទៅយើងគួរដាក់អក្សរបុព្វបទ (Prefix) ពីមុខឈ្មោះ Table ដូចជា tbl_students, tbl_users ដើម្បីងាយស្រួលបែងចែក Table ក្នុង Database និងជៀសវាងការជាន់ឈ្មោះជាមួយ Reserved Keywords របស់ SQL!

Data Type Selection: Balancing Storage Capacity, Precision, and Performance

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY
Data Type កម្រិតទំហំ (Capacity/Range) ករណីប្រើប្រាស់សមស្រប (Use Cases)
INT -2,147,483,648 ដល់ 2,147,483,647 ប្រើសម្រាប់ ID (Primary Key), ចំនួនសរុប, Stock, លេខរៀង

Financial Precision: Floating-point Inaccuracy vs Exact Fixed-point Decimal

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY

គ្រោះថ្នាក់នៃ `FLOAT` / `DOUBLE`

ប្រភេទ FLOAT និង DOUBLE គឺជាលេខប្រហាក់ប្រហែល (Approximate values) តាមស្តង់ដារ IEEE 754។

  • វាកើតមានបញ្ហា Floating-Point Rounding Error (បាត់បង់សេនពេលបូកដកគុណចែក)។
  • ឧទាហរណ៍៖ 0.1 + 0.2 = 0.30000000000000004!
  • ក្នុងប្រព័ន្ធគណនេយ្យ ធនាគារ និង E-commerce វាបណ្តាលឱ្យទិន្នន័យប្រាក់មិនត្រូវគ្នានឹងរបាយការណ៍សវនកម្ម!

ដំណោះស្រាយ ៖ ប្រើ `DECIMAL(10,2)`

DECIMAL(M,D) រក្សាទុកលេខក្បៀសជា Exact Numeric Type ឥតលម្អៀងឡើយ ៖

  • M (Precision) ៖ ចំនួនខ្ទង់សរុប (រាប់ទាំងមុខ និងក្រោយក្បៀស)។
  • D (Scale) ៖ ចំនួនខ្ទង់ខាងក្រោយក្បៀស (សម្រាប់លុយ គឺ 2 ខ្ទង់)។
  • DECIMAL(10,2) អាចផ្ទុកប្រាក់បានរហូតដល់ $99,999,999.99 ដោយសុវត្ថិភាព ១០០%!

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY

Primary Key & Auto Increment

  • Primary Key (PK) ៖ កូនសោចម្បងដែលធានាថារាល់ Record នីមួយៗក្នុង Table ត្រូវតែមានតម្លៃសម្គាល់ខ្លួនមិនជាន់គ្នាឡើយ (លក្ខណៈ UNIQUE + NOT NULL)។
  • AUTO_INCREMENT (AI) ៖ មុខងារបង្កើនលេខ ID ឡើងដោយស្វ័យប្រវត្តិ (1, 2, 3...) រាល់ពេលមាន Record ថ្មីបញ្ចូលមក ដោយ Developer មិនបាច់សរសេរលេខ ID ដោយដៃឡើយ។

Field Constraints សំខាន់ៗ

  • NOT NULL ៖ បង្ខំឱ្យ Field នោះត្រូវតែមានទិន្នន័យ ហាមទទេស្អាត។

៧.៤.១ Hard Delete ធៀបនឹង Enterprise Soft Delete

Data Lifecycle Strategies: Permanent Removal vs. Logical Audit Preservation

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY

១. Hard Delete (`DELETE FROM`)

លុបទិន្នន័យដាច់ចេញពី Storage Disk ជារៀងរហូត មិនអាច Recover ឡើងវិញបានឡើយ។

DELETE FROM tbl_students WHERE id = 3;

គុណវិបត្តិ ៖ បាត់បង់ប្រវត្តិប្រតិបត្តិការ (Audit Trail) និងអាចបណ្តាលឱ្យខូច Foreign Key Constraints។

២. Soft Delete (Logical Deletion)

មិនលុប Record ចេញពី Disk ទេ គ្រាន់តែប្តូរ Flag is_deleted = 1 ដើម្បីលាក់កុំឱ្យបង្ហាញ ៖

-- 1. Soft Delete Flag Update UPDATE tbl_students SET is_deleted = 1 WHERE id = 2; -- 2. ទាញយកតែ Record ដែលសកម្ម SELECT * FROM tbl_students WHERE is_deleted = 0;

គុណសម្បត្តិ ៖ អាច Restore ទិន្នន័យវិញបាន និងរក្សាប្រវត្តិរាយការណ៍បាន ១០០%។

៧.ឃ. ចម្លើយសំណួរបកស្រាយ (Q7.1 ដល់ Q7.5)

Detailed Conceptual Explanations: Primary Keys, Auto Increment, WHERE Clauses, and Soft Deletes

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY

• ចម្លើយ Q7.1, Q7.2 & Q7.3

• Q7.1 (Primary Key & AI) ៖ Primary Key ធានាថារាល់ Record មាន Unique ID មិនស្ទួនគ្នាដាច់ខាត។ Auto Increment ឱ្យ MySQL បង្កើតលេខ ID (1, 2, 3...) ស្វ័យប្រវត្តិ មិនបាច់បញ្ចូលដោយដៃឡើយ។

• Q7.2 (VARCHAR vs TEXT) ៖ VARCHAR សម្រាប់អត្ថបទខ្លីប្រែប្រួលទំហំ (ឈ្មោះ, អ៊ីមែល) មិនសូវស៊ី Disk Space។ TEXT សម្រាប់អត្ថបទវែងៗខ្លាំង (អត្ថបទ Blog, ព័ត៌មានលម្អិត)។

• Q7.3 (WHERE Clause) ៖ WHERE ប្រើប្រាស់សម្រាប់ Filter ចម្រាញ់យកតែ Record ណាដែលផ្ទៀងផ្ទាត់ត្រូវតាមលក្ខខណ្ឌជាក់លាក់ (ឧ. WHERE major = 'CS')។

• ចម្លើយ Q7.4 & Q7.5

• Q7.4 (DECIMAL vs FLOAT) ៖ FLOAT មានបញ្ហា Floating-point Rounding Error (បាត់បង់សេនពេលគណនា)។ ឯ DECIMAL(10,2) រក្សាទុកក្បៀសច្បាស់លាស់ 100% សម្រាប់លុយកាក់។

• Q7.5 (Hard Delete vs Soft Delete) ៖ Hard Delete (DELETE FROM) លុបបាត់ចេញពី Disk មិនអាច Recover បានឡើយ។ Soft Delete (UPDATE ... SET is_deleted = 1) រក្សាទុក Record ដដែល តែលាក់វាមិនឱ្យបង្ហាញ រក្សាបាននូវ Audit Trail History។

• Q7.7 (Data Integrity Constraints) ៖ Constraints (NOT NULL, UNIQUE, DEFAULT) ការពារមិនឱ្យមានទិន្នន័យខុសច្បាប់ ឬទិន្នន័យស្ទួនចូលក្នុង Database បង្កើន Data Quality និងភាពជឿជាក់នៃប្រព័ន្ធ។

• ចម្លើយ Q7.8 & Q7.9

• Q7.8 (E-commerce Products Schema) ៖ បង្កើត tbl_products មាន id INT AUTO_INCREMENT PRIMARY KEY, title VARCHAR(100), price DECIMAL(10,2), stock INT, is_deleted TINYINT, និង created_at DATETIME។

• Q7.9 (Full SQL Script Pipeline) ៖ សរសេរ Script រួមបញ្ចូល CREATE DATABASE → CREATE TABLE → INSERT INTO → SELECT ... WHERE ... ORDER BY → UPDATE ... WHERE → Soft Delete។
