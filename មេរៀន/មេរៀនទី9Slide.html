៩.១.១ ការវាយប្រហារ SQL Injection (Concatenation Vulnerability)

Security Vulnerabilities: Direct String Concatenation and OWASP Top 10 Threats

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY
⚠️ និយមន័យ ៖ SQL Injection (SQLi) កើតឡើងនៅពេល Developer យកទិន្នន័យពី User ($_POST, $_GET) ទៅតភ្ជាប់ String ផ្ទាល់ (.) ជាមួយ SQL Command ដោយពុំបានបន្សាប ឬ Filter។

C4 កាយវិភាគវិទ្យានៃ Payload ព្យាបាទ

  • Single Quote (') ៖ ប្រើសម្រាប់បំបែកចេញពីតម្លៃ String ដើមក្នុងសំណួរ SQL ដើម្បីចាប់ផ្តើមបញ្ជាកូដថ្មី។
  • Tautology (OR '1'='1') ៖ បង្កើតលក្ខខណ្ឌដែលតែងតែពិត (Always True) ធ្វើឱ្យសំណួរទាញយកគ្រប់ទិន្នន័យ។
  • SQL Comment (-- ឬ #) ៖ លុបចោលលក្ខខណ្ឌផ្ទៀងផ្ទាត់ខាងក្រោយ (ដូចជា Password Check)។

កូដគ្រោះថ្នាក់ (Vulnerable Anti-Pattern)

៩.១.២ ដំណោះស្រាយ ៖ PDO Prepared Statements Architecture

Two-Phase Execution Model: Compile Time Preparation vs Execution Time Binding

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY
🛡️ Prepared Statements ៖ បំបែកដាច់ស្រឡះរវាង គ្រោងឆ្អឹងកូដ SQL (Query Skeleton) និង ទិន្នន័យរបស់ User (Data Value) ជា ២ ដំណាក់កាល។

C2 យន្តការពីរកំណាត់ (2-Phase Model)

  1. ដំណាក់កាល ១ (Prepare Phase) ៖ បញ្ជូនតែប្រយោគ SQL Skeleton ជាមួយ Placeholder (:code) ឱ្យ MySQL Pre-compile ជាមុន។
  2. ដំណាក់កាល ២ (Execute Phase) ៖ បញ្ជូន Data ទៅតាមក្រោយ។ Database នឹងចាត់ទុក Data ជា Literal String ធម្មតា មិនយកមក Compile ជាកូដបញ្ជា SQL ឡើយ!

ឧទាហរណ៍កូដការពារសុវត្ថិភាព

<?php // ១. Prepare: Compile គ្រោងឆ្អឹង SQL ទុកជាមុន $stmt = $pdo->prepare("SELECT * FROM tbl_products WHERE pcode = :code"); // ២. Execute: បញ្ជូន Data Value ទៅចងភ្ជាប់ $stmt->execute([':code' => $userInput]); $product = $stmt->fetch(); ?>
