៦.១.១ និយមន័យ Encapsulation & Data Hiding

Core OOP Pillars: Bundling State with Operations and Enforcing Data Boundaries

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY
🎯 គោលគំនិត ៖ Encapsulation (ការខ្ចប់ និងលាក់ទិន្នន័យ) គឺជាសសរទ្រូងទី១ នៃ OOP ដែលធ្វើការខ្ចប់ Data (Properties) និង Operations (Methods) ចូលគ្នាក្នុង Class តែមួយ ព្រមទាំង លាក់បាំងបដិសេធ (Data Hiding) ការចូលប្រើប្រាស់ទិន្នន័យសំខាន់ៗដោយផ្ទាល់ពីខាងក្រៅ។

C1 ហេតុអ្វីចាំបាច់ត្រូវមាន Encapsulation?

  • Data Protection ៖ ការពារកុំឱ្យកូដខាងក្រៅ Class កែប្រែទិន្នន័យសំខាន់ៗដោយបំពាន (ឧទាហរណ៍៖ កែប្រែសមតុល្យប្រាក់ធនាគារ $balance = -99999;)។
  • Validation Control ៖ រាល់ការកែប្រែទិន្នន័យ ត្រូវតែឆ្លងកាត់ការត្រួតពិនិត្យភាពត្រឹមត្រូវជាមុន (Validation Rules) តាមរយៈ Methods។
  • Flexibility & Maintenance ៖ យើងអាចកែប្រែ Logic ផ្ទៃក្នុងរបស់ Class បានដោយមិនប៉ះពាល់ដល់កូដខាងក្រៅដែលហៅប្រើប្រាស់ឡើយ។

គំរូប្រៀបធៀបក្នុងជីវិតពិត

គ្រាប់ថ្នាំពេទ្យ (Capsule) ៖ ឱសថត្រូវបានខ្ចប់ការពារនៅក្នុងស្រទាប់សំបកថ្នាំ ដើម្បីការពារគុណភាពសារធាតុខាងក្នុងមិនឱ្យខូចខាតពីបរិយាកាសខាងក្រៅ។

ដូចគ្នានេះដែរ នៅក្នុង Class ទិន្នន័យសំខាន់ៗត្រូវបានលាក់បាំងក្នុងកម្រិត private ឬ protected ហើយមានតែ Public Methods (Getters/Setters) ប៉ុណ្ណោះដែលដើរតួជាច្រកចេញចូលផ្លូវការ។

Lesson 6: Encapsulation & Inheritance 6.1.1 • Encapsulation Definition ស្លាយទី ៤ នៃ ៣២

កម្រិតសិទ្ធិមើលឃើញទាំង ៣ (Access Modifiers)

Visibility Scopes: public, protected, and private Architectural Directives

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY

១. `public` (សាធារណៈ)

ជាកម្រិតបើកចំហរទូលាយបំផុត។ Member (Property ឬ Method) ដែលប្រកាសជា public អាចចូលប្រើប្រាស់បានពី គ្រប់ទីកន្លែង ទាំងក្នុង Class, ក្នុង Child Class និងពីខាងក្រៅ Class (Global Scope)។

public string $username;

២. `protected` (ការពារ)

ជាកម្រិតការពារមធ្យម។ Member ដែលប្រកាសជា protected អាចចូលប្រើប្រាស់បានតែនៅក្នុង Class ខ្លួនឯង និងក្នុង Class កូន (Child Classes) ដែលបន្តពូជពីវាប៉ុណ្ណោះ។ ខាងក្រៅ Class មិនអាចចូលប្រើបានឡើយ!

protected string $email;

៣. `private` (ឯកជន)

ជាកម្រិតរឹតបន្តឹងបំផុត។ Member ដែលប្រកាសជា private អាចចូលប្រើប្រាស់បានតែនៅក្នុង Class ដើមខ្លួនឯងតែ ១ គត់។ សូម្បីតែ Child Class ក៏គ្មានសិទ្ធិចូលប្រើដោយផ្ទាល់បានដែរ!

private string $password;

Controlled Access: Public Gateways for Reading and Writing Encapsulated Properties

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY
🎯 គោលគំនិត ៖ កំណត់ Properties សំខាន់ៗជា private រួចបង្កើត Public Methods ពីរក្រុម គឺ Getter (សម្រាប់អានទិន្នន័យ) និង Setter (សម្រាប់កែប្រែទិន្នន័យដោយមាន Validation)។

C2 Getter Method (អានទិន្នន័យ)

  • គោលបំណង ៖ ប្រើប្រាស់សម្រាប់ ទាញយក/អាន (Read) តម្លៃ Property មកបង្ហាញខាងក្រៅ។
  • អនុវត្ត ៖ ដាក់ឈ្មោះផ្តើមដោយ get...()។
  • Return Type ៖ ត្រូវកំណត់ Return Type ឱ្យត្រូវគ្នានឹងប្រភេទ Property នោះ។
public function getBalance(): float { return $this->balance; }

C3 Setter Method (កែប្រែទិន្នន័យ)

  • គោលបំណង ៖ ប្រើប្រាស់សម្រាប់ កំណត់/កែប្រែ (Write) តម្លៃ Property ដោយឆ្លងកាត់ការផ្ទៀងផ្ទាត់ (Validation)។
  • អនុវត្ត ៖ ដាក់ឈ្មោះផ្តើមដោយ set...()។
  • Return Type ៖ ជាទូទៅមាន Return Type ជា void។
public function setBalance(float $amt): void { if ($amt >= 0) { $this->balance = $amt; } }

The Second Pillar of OOP: Base Classes, Derived Classes, and the DRY Principle

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY
🎯 គោលគំនិត ៖ Inheritance (ការបន្តពូជ) អនុញ្ញាតឱ្យ Class ថ្មីមួយ (Child / Derived Class) បន្តពូជទាញយក Properties និង Methods ពី Class ដើម (Parent / Base Class) មកប្រើប្រាស់ស្វ័យប្រវត្តិតាមរយៈពាក្យគន្លឹះ extends។

C3 រចនាសម្ព័ន្ធមេ និងកូន

  • Parent (Base) Class ៖ ជា Class ថ្នាក់លើដែលមានផ្ទុក Properties និង Methods សាមញ្ញរួម។
  • Child (Derived) Class ៖ ជា Class កូនដែលបន្តពូជពី Parent Class តាមរយៈពាក្យគន្លឹះ extends។
  • Class កូនទទួលបាននូវរាល់ Members ទាំងឡាយណាដែលជា public និង protected របស់ Class មេ។

គោលការណ៍ DRY (Don't Repeat Yourself)

បើគ្មាន Inheritance ទេ នៅពេលយើងបង្កើត Class Admin, Teacher, និង Student យើងត្រូវ Copy-Paste Properties $username, $email, និង Password ដដែលៗ ៣ ដង។

ជាមួយនឹង Inheritance យើងសរសេរកូដរួមតែម្តងគត់ក្នុង Parent Class User រួចឱ្យ Class ផ្សេងទៀតបន្តពូជ extends User ជាការស្រេច!

Polymorphic Behavior: Redefining Parent Methods to Suit Child Specializations

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY
🎯 គោលគំនិត ៖ Method Overriding គឺជាការសរសេរឡើងវិញ (Redefine) នូវ Method របស់ Parent Class នៅក្នុង Child Class ដើម្បីកែប្រែ ឬបន្ថែមតក្កវិទ្យាថ្មីសមស្របតាមតម្រូវការជាក់ស្តែងរបស់ Class កូន។

C4 គោលការណ៍ Method Overriding

  • Child Class អាចប្រកាស Method ដែលមាន ឈ្មោះដូចគ្នា និង Parameters ដូចគ្នា ទៅនឹង Parent Class។
  • នៅពេលហៅ Method នោះលើ Object កូន នោះ PHP នឹងរត់ Method ថ្មីរបស់ Child Class ដោយស្វ័យប្រវត្តិ (Polymorphism)។
  • Visibility របស់ Overriding Method ត្រូវតែមានកម្រិតស្មើ ឬទូលាយជាង Parent Method (មិនអាចបង្រួមពី public មក private បានឡើយ)។

C3 ពាក្យគន្លឹះ `parent::`

នៅពេលធ្វើ Method Overriding ពេលខ្លះយើងមិនចង់សរសេរចោល Method របស់ Parent Class ទាំងស្រុងនោះទេ គឺយើងចង់ ហៅ Method ដើមមកដំណើរការសិន រួចសឹមបន្ថែម Logic ថ្មី។

public function getSalaryDetails(): string { // ហៅ Method ដើមរបស់ Parent Class return parent::getSalaryDetails() . " + Bonus: " . $this->bonus; }

ជួយកាត់បន្ថយកូដស្ទួន និងរក្សាភាពស៊ីសង្វាក់គ្នានៃប្រព័ន្ធ។

ការហៅ `parent::__construct()`

ជាទម្លាប់ដ៏សំខាន់បំផុតក្នុង OOP! នៅពេល Child Class មាន Constructor ផ្ទាល់ខ្លួន វាតម្រូវឱ្យហៅ parent::__construct(...) ជាមុន ដើម្បីផ្ញើតម្លៃ Properties ដើមឱ្យ Parent Class ធ្វើការ Initialize ឱ្យបានត្រឹមត្រូវ។

public function __construct(string $name, float $sal, float $bonus) { parent::__construct($name, $sal); // Run Parent Constructor $this->bonus = $bonus; // Initialize Child Property }

C4 អំពី `#[\Override]` Attribute (PHP 8.3+)

ក្នុងកំណែចាស់ ប្រសិនបើ Developer វាយអក្ខរាវិរុទ្ធឈ្មោះ Method ខុសដោយអចេតនា (ឧ. សរសេរ getSalaryDetail() គ្មានអក្សរ s) PHP នឹងយល់ថាជា Method ថ្មី មិនមែនជា Overriding ឡើយ ដែលបង្កើតជា Silent Bug ដ៏គ្រោះថ្នាក់!

  • ចាប់ពី PHP 8.3+ ការបន្ថែម #[\Override] ពីលើ Method ក្នុង Child Class នឹងបញ្ជាឱ្យ PHP Compiler ផ្ទៀងផ្ទាត់ ថា Method នោះពិតជាមានក្នុង Parent Class។
  • ប្រសិនបើគ្មាន ឬវាយខុស វានឹងបោះ Fatal Compile Error ភ្លាមៗ!

១. Encapsulation & Data Hiding

២. Visibility Modifiers Matrix

៣. Class Inheritance & DRY

៤. Overriding & `parent::`

៧.ឃ. ចម្លើយសំណួរបកស្រាយ (Q6.1 ដល់ Q6.5)

Detailed Conceptual Explanations: Access Modifiers, Data Protection, Getters/Setters, and DRY

សាកលវិទ្យាល័យអង្គរ ANGKOR UNIVERSITY

• ចម្លើយ Q6.1, Q6.2 & Q6.3

• Q6.1 (Access Modifiers) ៖ public ចូលប្រើបានគ្រប់ទីកន្លែង។ protected ចូលប្រើបានតែក្នុង Class ខ្លួនឯង និង Child Classes។ private ចូលប្រើបានតែក្នុង Class ខ្លួនឯង ១ គត់។

• Q6.2 (Encapsulation Purpose) ៖ ជាការលាក់ទិន្នន័យ (Data Hiding)។ មិនត្រូវប្រកាស public ទាំងអស់ទេ ព្រោះកូដក្រៅអាចបំពានកែប្រែទិន្នន័យខុសច្បាប់ (ឧ. $balance = -500) ដោយរំលង Validation។

• Q6.3 (Getters & Setters) ៖ Getter អនុញ្ញាតឱ្យអានតម្លៃ private property ដោយសុវត្ថិភាព។ ឯ Setter អនុញ្ញាតឱ្យកែប្រែតម្លៃ property ដោយឆ្លងកាត់ Validation Pipeline។

• ចម្លើយ Q6.4 & Q6.5

• Q6.4 (Inheritance & DRY) ៖ Inheritance អនុញ្ញាតឱ្យ Child Class ទាញយកកូដពី Parent Class មកប្រើប្រាស់ស្វ័យប្រវត្តិ ធ្វើឱ្យយើងមិនបាច់សរសេរ Properties/Methods ដដែលៗឡើយ (គោលការណ៍ DRY)។
