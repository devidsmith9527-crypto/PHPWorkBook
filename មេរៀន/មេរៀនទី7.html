៧.១.១ គំនិតគ្រឹះនៃ Relational Database & phpMyAdmin Architecture C2

ក. និយមន័យ (Definition)៖
• Database (មូលដ្ឋានទិន្នន័យ)៖ គឺជាប្រព័ន្ធសាំងខាងក្នុង Memory/Disk សម្រាប់រៀបចំ រក្សាទុក និងគ្រប់គ្រងទិន្នន័យឱ្យមានរបៀបរៀបរយ។
• RDBMS (Relational Database Management System)៖ គឺជាប្រព័ន្ធគ្រប់គ្រងទិន្នន័យដែលរៀបចំទិន្នន័យជាទម្រង់ **តារាងទិន្នន័យ (Tables)** មានជួរឈរ (**Columns / Fields**) និងជួរដេក (**Rows / Records**) ព្រមទាំងភ្ជាប់ទំនាក់ទំនងរវាងតារាងតាមរយៈ **Keys (PK & FK)**។ MySQL និង MariaDB គឺជា RDBMS ដ៏ពេញនិយមបំផុតលើពិភពលោក។
• phpMyAdmin GUI Interface: គឺជា Web Application បង្កើតឡើងដោយ PHP សម្រាប់សម្រួលដល់ Web Developer ក្នុងការគ្រប់គ្រង MySQL Server តាមរយៈ Web Browser ដោយមិនបាច់សរសេរ Command-line សញាំញាំឡើយ។
ខ. រចនាសម្ព័ន្ធតារាងទិន្នន័យ (Table Structural Components)៖
សមាសភាគ (Component) ឈ្មោះបច្ចេកទេស Database ការពន្យល់ និងឧទាហរណ៍
Table (តារាង) Entity / Relation សំណុំទិន្នន័យប្រធានបទតែមួយ (ឧ. tbl_students)
Column (ជួរឈរ) Field / Attribute លក្ខណៈនៃទិន្នន័យ (ឧ. id, fullname, email)
Row (ជួរដេក) Record / Tuple ទិន្នន័យម្នាក់ៗជាក់ស្តែង (ឧ. Record របស់និស្សិត សុខ ជា)
Primary Key (PK) Unique Identifier កូនសោចម្បងសម្គាល់ Record នីមួយៗមិនឱ្យជាន់គ្នាដាច់ខាត
គ. របៀបចូលប្រើប្រាស់ phpMyAdmin តាមរយៈ XAMPP Control Panel៖
1. បើក XAMPP Control Panel -> ចុច [Start] លើ Module Apache និង MySQL 2. បើក Web Browser -> វាយអាសយដ្ឋាន៖ http://localhost/phpmyadmin/ 3. ឬ ចុចប៊ូតុង [Admin] នៅត្រង់ជួរ MySQL ក្នុង XAMPP Control Panel
ឃ. បទពិសោធន៍សាស្ត្រាចារ្យ (Teacher Insights - Table Naming Conventions)៖

ក. ការជ្រើសរើស Data Types សំខាន់ៗ (MySQL Data Types Selection)៖
Data Type កម្រិតទំហំ (Capacity/Range) ករណីប្រើប្រាស់សមស្រប (Use Cases)
INT -2,147,483,648 ដល់ 2,147,483,647 ប្រើសម្រាប់ ID (Primary Key), ចំនួនសរុប, លេខរៀង
VARCHAR(length) អក្សរប្រែប្រួលទំហំ (១ ដល់ ៦៥,៥៣៥ ចរិត) ប្រើសម្រាប់ ឈ្មោះ, អ៊ីម៉ែល, លេខទូរស័ព្ទ, លេខសម្ងាត់
TEXT អត្ថបទវែង (រហូតដល់ ៦៥,៥៣៥ ចរិត) ប្រើសម្រាប់ ជីវប្រវត្តិ, ព័ត៌មានលម្អិត, អត្ថបទមេរៀន/Blog
DECIMAL(M,D) លេខមានក្បៀសច្បាស់លាស់ (Precision) ប្រាក់ខែ, តម្លៃទំនិញ (ឧ. DECIMAL(10,2) គឺ $99,999,999.99)
DATETIME YYYY-MM-DD HH:MM:SS កាលបរិច្ឆេទបង្កើត ឬធ្វើបច្ចុប្បន្នភាព (created_at)
ខ. គំនិតគ្រឹះនៃ Keys & Field Constraints៖
• Primary Key (PK): កូនសោចម្បងដែលធានាថា Row នីមួយៗមិនជាន់គ្នាឡើយ (`UNIQUE` + `NOT NULL`)។
• Auto Increment (AI): កំណត់ឱ្យ MySQL បន្ថែមលេខ ID ឡើងស្វ័យប្រវត្តិ (1, 2, 3, ...) រាល់ពេលមាន Record ថ្មីបញ្ជូល។
• Foreign Key (FK): កូនសោក្រៅដែលភ្ជាប់ទំនាក់ទំនងរវាង Table មួយ ទៅកាន់ Primary Key នៃ Table មួយទៀត។
• NOT NULL Constraint: កំណត់បម្រាមមិនឱ្យ Field នោះទទេរស្អាត (ត្រូវតែមានទិន្នន័យជានិច្ច)។
គ. បទពិសោធន៍សាស្ត្រាចារ្យ (Avoid Float/Double for Currency!)៖
• សុំកុំប្រើ `FLOAT` ឬ `DOUBLE` សម្រាប់រក្សាទុកលុយកាក់ដាច់ខាត! ព្រោះវាមាន Floating-point Precision Issue (គណនាប្រាក់បាត់សេន)។ ត្រូវតែប្រើប្រាស់ DECIMAL(10,2) ជានិច្ចសម្រាប់ការងារទាក់ទងនឹងប្រាក់ខែ ឬតម្លៃទំនិញ E-commerce!

DELETE FROM tbl_students

គ. យុទ្ធសាស្ត្រ Soft Delete ក្នុងប្រព័ន្ធ Enterprise (Soft Delete Pattern)៖
ក្នុងប្រព័ន្ធធំៗ (ដូចជា Banking ឬ E-commerce) គេ **ប្រឆាំងដាច់ខាតមិនឱ្យប្រើ Hard Delete** ឡើយ ព្រោះអាចធ្វើឱ្យបាត់បង់ប្រវត្តិប្រតិបត្តិការ (Audit Logs)។ គេអនុវត្ត **Soft Delete** ដោយបន្ថែម Flag Field (ដូចជា is_deleted TINYINT DEFAULT 0)៖
soft_delete_strategy.sql
-- 1. ធ្វើ Soft Delete ដោយគ្រាន់តែប្តូរ Flag is_deleted = 1
UPDATE tbl_students 
SET is_deleted = 1 
WHERE id = 2;

-- 2. ពេល SELECT ទាញតែ Record ណាដែលមិនទាន់លុប (is_deleted = 0)
SELECT * FROM tbl_students 
WHERE is_deleted = 0;
ឃ. ការព្រមានដ៏សំខាន់ (The Disaster of Missing WHERE Clause!)៖
• ប្រយ័ត្នជីវិតចុងក្រោយរបស់ Developer! ប្រសិនបើអ្នកភ្លេចសរសេរ WHERE Clause ក្នុងបញ្ជា UPDATE ឬ DELETE នោះ MySQL នឹងកែប្រែ ឬ **លុបទិន្នន័យទាំងអស់ដែលមានក្នុង Table នោះចោលស្អាតគ្មានសល់**! ត្រូវតែតេស្ត Query ជាមួយ `SELECT` ជាមុនជានិច្ច!

៧.ឃ. ចម្លើយសំណួរបកស្រាយ (Answers to Explanatory Questions Q7.1 - Q7.5)
[កម្រិតស្រាល - Light/Easy Level Solutions]
• ចម្លើយ Q7.1 (Primary Key & Auto Increment Role)៖
• Primary Key: ធានាថារាល់ Record មាន Unique ID មិនស្ទួនគ្នាដាច់ខាត។
• Auto Increment: ឱ្យ MySQL បង្កើតលេខ ID (1, 2, 3...) ស្វ័យប្រវត្តិ មិនបាច់បញ្ចូលដោយដៃឡើយ។
• ចម្លើយ Q7.2 (VARCHAR vs TEXT)៖
• `VARCHAR`: សម្រាប់អត្ថបទខ្លីប្រែប្រួលទំហំ (ឧ. ឈ្មោះ, អ៊ីម៉ែល) មិនសូវស៊ី Disk Space។
• `TEXT`: សម្រាប់អត្ថបទវែងៗខ្លាំង (ឧ. អត្ថបទ Blog, ព័ត៌មានលម្អិត)។
• ចម្លើយ Q7.3 (WHERE Clause in SELECT)៖
`WHERE` ប្រើប្រាស់សម្រាប់ Filter ចម្រាញ់យកតែ Record ណាដែលផ្ទៀងផ្ទាត់ត្រូវតាមលក្ខខណ្ឌ (ឧ. `WHERE major = 'CS'`)។
[កម្រិតមធ្យម - Medium Level Solutions]
• ចម្លើយ Q7.4 (DECIMAL vs FLOAT for Currency)៖
`FLOAT` មានបញ្ហា Floating-point Rounding Error (បាត់បង់សេនពេលគណនា)។ ឯ `DECIMAL(10,2)` រក្សាទុកក្បៀសច្បាស់លាស់ 100% សម្រាប់លុយកាក់។
• ចម្លើយ Q7.5 (Hard Delete vs Soft Delete)៖
• Hard Delete (`DELETE FROM`): លុបបាត់ចេញពី Disk មិនអាច Recover បានឡើយ។
• Soft Delete (`UPDATE ... SET is_deleted = 1`): រក្សាទុក Record ដដែល តែលាក់វាមិនឱ្យបង្ហាញ រក្សាបាននូវ Audit Trail History។
